# 合并前复核规范（PreMergeCommitCheckListSpec）

> 所属：FinvQuant 开发规范 · 存放：`Docs/CheckList/`
> 适用范围：把 `feat/*` 合入目标分支（`main` 或集成分支）前的最后一次复核与功能验收。
> 关联：[`PreCommitCheckListSpec.md`](PreCommitCheckListSpec.md)（提交者自检）、[`GitSpec.md`](../DevSpec/GitSpec.md)（版本号 / tag / CI 产物）、[`ApiSpec.md`](../DevSpec/ApiSpec.md)、[`DbSchemaSpec.md`](../DevSpec/DbSchemaSpec.md) §0、[`DocSpec.md`](../DevSpec/DocSpec.md) §4。
> 本清单的定位：**复核人验收**。提交者自检清单见 `PreCommitCheckListSpec.md`，两者不重复。

## 1. 角色与时机

- 时机：`PreCommitCheckListSpec` 已全绿（提交完成）→ 合并前。
- 复核人：**不是本次提交者**。单人项目无他人时，按本清单逐条留证据（命令 + 输出），不得口头"看过了"。
- 结论只有两种：**通过** 或 **打回**。打回必须写「打回依据 + 对应 `M` 编号」，不含"建议优化"这类无法验收的措辞。

## 2. 三类复核，不要混为一谈

| 类别 | 看什么 | 证据形态 |
|------|--------|----------|
| 代码复核 | diff 本身：正确性、边界、命名、无死代码 | 行级评论 / 结论 |
| 一致性复核 | 需求 ↔ 代码 ↔ 迁移 ↔ 接口文档 ↔ 菜单文档 | 文件路径 + 关键行 |
| 功能验收 | 真的跑起来，输入用例，观察输出 | 命令 + 输出片段（或截图路径） |

只有第一类通过 = 没验收，不算可合并。

## 3. 按变更类型定复核深度

复核不是"全部条目都走一遍"，按变更类型取范围；**涉及其中的事故编号，逐条验判据，不接受口头保证**。
事故编号 `R1…R16` 的定义见 [`PreCommitCheckListSpec.md`](PreCommitCheckListSpec.md) §3。

| 变更类型 | 复核范围 | 必须验的事故判据 |
|----------|----------|------------------|
| 仅 Go 后端 | M1、M2、M6 | R6（URL 编码/分片）、R7（生成列） |
| 接口契约 | M1、M2、M4、M5、M6 | 上述 + 状态码与 `ErrorCodeSpec` 对齐 |
| 前端页面 | M1、M2、M5（M5.3 边界必做）、M6 | R10（下拉/表格口径）、R11（命名） |
| 数据库迁移 | M1、M2、M3、M5.6、M6 | R1、R2、R3、R4、R5、R8、R12、R13 |
| 文档/规范 | M1、M4、M6（代码类可免） | R9（表格合法性，`go test ./internal/docs`） |
| 部署/构建 | M1、M3、M5.1、M5.5、M5.6、M6 | R15（构建参数）、R16（迁移与文档同步） |

**迁移类改动是本项目返工最集中的地方**：M3 九条 + R1–R8 是硬要求，任一项无法给证据即打回。

## 5. 证据要求

1. **每条涉及项必须可复核**：写命令 + 关键输出（3～10 行即可），不写"已验证""没问题"。
2. 数据类结论必须给**数字**：迁移后版本号、行数、`fk` 数、差异计数。
3. 前端验收给**页面路径 + 产物哈希**；接口验收给**方法与状态码**。
4. 证据与代码同版本：跑了旧二进制就不算。

PR 描述模板（不超过 15 行）：

```text
需求：11109 字典筛选控件规范
改动：Docs/DevSpec/DictFilterSpec.md（新增）；AGENTS.md 索引 1 行
CommitCheck：C1–C7, C12, C17–C20（C8/C9 见下）
迁移：无
验收：
  go test ./internal/docs/ -count=1        PASS
  git diff --stat                          仅 2 文件
结论：通过 / 打回（依据 Mx.y）
```

## 6. 必须打回的情形

- 空库全量迁移不通，或迁移修改了历史脚本；
- 收敛校验依赖行数阈值、可能阻塞启动（`M3.5`）；
- 未授权改表结构 / 改受保护文档；
- 明文密钥入库；
- 测试靠 `t.Skip` / 注释断言变绿；
- 只有代码复核、没有功能验收证据（`M5` 全空）；
- 接口实现与 `.yml` 不一致，或 `Docs/CHANGELOG.md` 缺失；
- 提交者自检清单未填或填 `-`。

## 7. 新增/修改条目的规则

1. **来源必须有据**：真实事故（需求号/提交号）或既有规范条款；不接受凭感觉加的条目。
2. **判据可核对**：能用命令或观察结果证伪；禁止"性能可接受""代码清晰"这类无法判定的描述。
3. **不与 `PreCommitCheckListSpec` 重复**：提交者能自查的不进本清单；本清单只装"需他人复核或需实测"的项。
4. 编号制 `M<组>.<序>`，只增不改；作废保留并标 `（已废止：原因）`。
5. 新增条目同步 `Docs/CHANGELOG.md`。
