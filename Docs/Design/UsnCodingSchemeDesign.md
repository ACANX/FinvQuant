# usn 统一证券编号编制方案（设计稿）

> 所属：`public.finv_security.usn`（`V300221` 已加列：`INTEGER`、可空、无默认值）
> 状态：**草案**，待确认决策点后落地（见 §7）
> 关联需求：11306（加列）、11307（本方案落地，待登记）
> 数据基线：`public.finv_security` 实测 23,742 行（2026-11-18，本地 Docker `finv` 库）

## 1. 背景与目标

`usn`（Unified Security Number）是证券的内部统一编号，用于跨市场、跨品种的稳定标识与排序。
`usc` 是人类可读的统一证券代码（`SH0001` / `00700` / `AAPL`），`usn` 则是**纯数字**的可索引编号。

目标：

1. **全局唯一**：任意两个证券的 `usn` 不相等；
2. **可解析**：按前缀能反推市场与类型（沪/深/京/港股证券/港股指数）；
3. **可扩展**：为美股、加密、外汇、期货等预留号段；
4. **可回填**：存量行能按 `security_code` 逐批生成，生成规则写在 SQL 里可复核。

## 2. 规则草案（用户 2026-11-18 给定）

| 市场 | 前缀 | 代码位 | 拼接形式 | 示例 |
|---|---|---|---|---|
| 沪市 | `11` | 6 位数字证券代码 | `11` + 代码 | `600000` → `11600000` |
| 深市 | `12` | 6 位数字证券代码 | `12` + 代码 | `000001` → `12000001` |
| 京市 | `13` | 6 位数字证券代码 | `13` + 代码 | `920000` → `13920000` |
| 港股证券 | `150` | 5 位数字证券代码 | `150` + 代码 | `00700` → `15000700` |
| 港股指数 | `15` | 6 位数字指数代码 | `15` + 代码 | `800000` → `15800000` |

## 3. 号段空间

| 号段 | 起始 | 结束 | 容量 | 用途 |
|---|---|---:|---:|---|
| `11xxxxxx` | 11,000,000 | 11,999,999 | 1,000,000 | 沪市证券 |
| `12xxxxxx` | 12,000,000 | 12,999,999 | 1,000,000 | 深市证券 |
| `13xxxxxx` | 13,000,000 | 13,999,999 | 1,000,000 | 京市证券 |
| `150xxxxx` | 15,000,000 | 15,099,999 | 100,000 | 港股证券 |
| `15xxxxxx` | 15,000,000 | 15,999,999 | 1,000,000 | 港股指数（草案） |
| `14xxxxxx` | 14,000,000 | 14,999,999 | 1,000,000 | 未分配（预留） |
| `16xxxxxx` – `19xxxxxx` | 16,000,000 | 19,999,999 | 4,000,000 | 未分配（可给美股/加密/外汇/期货） |
| `2xxxxxxxx` 起 | — | — | — | 未分配（9 位，需 `BIGINT`） |

INTEGER 上限 2,147,483,647（10 位）：

- 8 位号段（11,000,000 – 19,999,999）远小于上限，**当前 `INTEGER` 足够**；
- 若将来扩到 9 位（`2xxxxxxxx`）也仍在 `INTEGER` 内；扩到 10 位（`9xxxxxxxxx`）时才需要 `BIGINT`。

## 4. 重叠分析

### 4.1 逐对比较

| 组合 | 是否重叠 | 说明 |
|---|---|---|
| 沪市 `11` vs 深市 `12` | 否 | 第 2 位不同（1 vs 2） |
| 沪市 `11` vs 京市 `13` | 否 | 第 2 位不同（1 vs 3） |
| 深市 `12` vs 京市 `13` | 否 | 第 2 位不同（2 vs 3） |
| 沪深京（`11`/`12`/`13`） vs 港股（`15`） | 否 | 第 2 位不同（1/2/3 vs 5） |
| 港股证券 `150`+5 vs 港股指数 `15`+6 | **规则上存在包含关系** | `150xxxxx`（15,000,000–15,099,999）完全落在 `15xxxxxx`（15,000,000–15,999,999）内 |

### 4.2 港股 15 段的实际操作风险

港股证券是 `150` + 5 位（第 3 位固定 `0`）；港股指数是 `15` + 6 位（第 3 位是指数代码首位）。

- 若港股指数代码**首位为 0**（如 `012345`）→ 拼接为 `15` + `012345` = `15012345`，**落入港股证券段**，冲突；
- 若港股指数代码**首位非 0**（当前实测为 `8`：`800000`–`800xxx`）→ 拼接为 `158xxxxx`，与证券段 `150xxxxx` 不冲突。

**实测（2026-11-18）**：港股指数 261 行，其中 255 行为 `800xxx`（6 位数字，首位 `8`），6 行为字母代码（`B...` / `H...`）；
因此**当前数据不会冲突**，但规则本身缺少「首位非 0」的约束，属于隐患。

### 4.2.1 港股方案「15+6 指数 / 151+5 证券」真实数据验证（2026-11-18）

按 `15`+6 位指数代码、`151`+5 位证券代码，用库里真实港股数据全量计算：

| 类型 | 行数 | usn 最小值 | usn 最大值 |
|---|---:|---:|---:|
| 港股证券（Stock / ETF / Fund） | 3,102 | 15,100,001 | 15,189,988 |
| 港股指数（6 位数字代码） | 255 | 15,800,000 | 15,800,935 |
| **交集** | **0** | — | — |

结论：**当前港股数据零冲突**。港股指数数字代码全部以 `8` 开头（`800000`–`800935`），
拼接后落在 `158xxxxx`，与证券段 `151xxxxx` 无交集。

唯一的理论冲突窗口：港股指数代码**首位为 `1`**（`100000`–`199999`）时会生成 `151xxxxx`，
与证券段重合。库里当前没有首位为 `1` 的港股指数代码。

## 5. 冲突与修正建议

### 5.1 港股 15 段（三选一，推荐 A）

| 方案 | 规则 | 优点 | 缺点 |
|---|---|---|---|
| **A（推荐）** | 港股证券 `150`+5；港股指数 `151`+5 | 两段完全不重叠（`150xxxxx` vs `151xxxxx`），解析按前 3 位判断 | 港股指数代码需从 6 位压到 5 位（去掉前导 `0` 或直接取后 5 位） |
| B | 港股证券 `150`+5；港股指数 `16`+6 | 15 段完全留给证券，彻底分离 | 占用预留段 `16` |
| C | 维持 `15`+6，但要求港股指数 6 位代码首位 ≥ 1 | 不改用户草案 | 规则带隐含约束，新增数据首 0 时会静默冲突，必须靠校验拦截 |

若选 C，生成时必须校验：`港股指数 && len(code)=6 && code[0]='0'` → 拒绝生成 `usn`（留空并告警）。

### 5.2 非数字代码兜底

| 场景 | 建议 |
|---|---|
| 沪市 8 位 `SH000002` | 先归一为 6 位（去 `SH` 前缀）再拼 `11`；归一失败则留空 |
| 深市 `CYB` / `SZCZ` / `BK0922` | `usn` 留空（NULL），等人工映射或后续规则 |
| 港股字母指数（`B...` / `H...`） | 留空 |
| 京市字母代码（`BS...`） | 留空 |

留空（NULL）符合当前列定义「可空 = 尚未分配」，不阻塞后续严格约束。

### 5.3 未覆盖市场

美股（字母）、加密（字母）、外汇（字母）、港股期货（字母）本期不编；建议预留：

| 号段 | 建议用途 |
|---|---|
| `16xxxxxx` | 美股 |
| `17xxxxxx` | 加密 |
| `18xxxxxx` | 外汇 |
| `19xxxxxx` | 期货 / 其它 |

### 5.4 唯一性

所有号段拼接后应全局唯一，建议在回填完成后建**唯一索引**（PostgreSQL 唯一索引允许多个 NULL，未分配行不受影响）：

```sql
CREATE UNIQUE INDEX CONCURRENTLY uq_finv_security_usn
    ON public.finv_security (usn) WHERE usn IS NOT NULL;
```

建索引前先用 §6.2 的冲突检测 SQL 确认 0 冲突。

## 6. 生成与校验建议

### 6.1 生成（SQL 表达式，可按市场分批回填）

```sql
-- 沪市：11 + 6 位代码（8 位带前缀的旧口径先归一）
CASE WHEN security_code ~ '^[0-9]{6}$' THEN ('11' || security_code)::int
     WHEN security_code ~ '^SH[0-9]{6}$' THEN ('11' || substr(security_code, 3))::int
END

-- 深市：12 + 6 位代码
CASE WHEN security_code ~ '^[0-9]{6}$' THEN ('12' || security_code)::int END

-- 京市：13 + 6 位代码
CASE WHEN security_code ~ '^[0-9]{6}$' THEN ('13' || security_code)::int END

-- 港股证券：150 + 5 位代码
CASE WHEN security_type IN ('Stock', 'ETF', 'Fund') AND security_code ~ '^[0-9]{5}$'
     THEN (15000000 + security_code::int) END

-- 港股指数（方案 A）：151 + 5 位（6 位代码取后 5 位）
CASE WHEN security_type = 'StockIndex' AND security_code ~ '^[0-9]{6}$'
     THEN (15100000 + (substr(security_code, 2))::int) END
```

> 说明：`150`+5 位与「15,000,000 + 5 位代码」等价，SQL 里用整数加法比字符串拼接更省事，但两者必须一致（见 §6.3 校验）。

### 6.2 冲突检测（回填前后都跑）

```sql
SELECT usn, count(*) AS rows, array_agg(usc) AS usc_list
  FROM public.finv_security
 WHERE usn IS NOT NULL
 GROUP BY usn
HAVING count(*) > 1;
```

### 6.3 一致性校验（防止两套生成口径漂移）

```sql
-- 抽样校验：沪市 usn 的前两位应为 11，且后 6 位 = security_code
SELECT count(*) FROM public.finv_security s
  JOIN public.finv_exchange e ON e.exchange_code = s.exchange_code
 WHERE e.exchange_flag = 'SH' AND s.usn IS NOT NULL
   AND s.usn <> (11 * 1000000 + s.security_code::int);
```

### 6.4 回填批次

按市场分批 `UPDATE ... WHERE usn IS NULL AND <市场条件>`，每批提交并记录行数；
`usn` 已非空的行不覆盖（幂等），后续严格约束（`NOT NULL` + 唯一索引）另起迁移。
