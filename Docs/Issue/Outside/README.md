# Docs/Issue/Outside — 未外发 Issue 草稿（草稿不入库，本 README 例外）

> 用途：存放**尚未提交给上游**、或包含内部环境信息（IP、账号、内网地址、生产库数据）的 Issue 草稿。
> 本目录下的**草稿一律不入库**（`.gitignore` 规则 `Docs/Issue/Outside/*`）；
> **唯独本 `README.md` 作为目录规范说明例外入库**（白名单 `!Docs/Issue/Outside/README.md`）。

## 1. 放什么

| 放这里 | 不放这里（放 `Docs/Issue/`） |
|--------|------------------------------|
| 还在起草、事实未核实的 Issue | 已提交给上游、可公开的 Issue 正文 |
| 含生产环境 IP / 账号 / 内网域名的复现记录 | 已脱敏的复现步骤 |
| 与上游沟通中、可能被否决的诉求 | 已采纳并落地的结论 |

## 2. 命名（与上层共用一套编号）

格式：**`ISSUE-O-NNNN-大驼峰标题.md`**

| 段 | 规则 |
|----|------|
| `ISSUE-O-` | 固定前缀（全大写），不做变动 |
| `NNNN` | 四位顺序号，从 `0001` 起，不足四位**左补 0**；只增不减、不得重号、**不得复用** |
| `大驼峰标题` | 英文 PascalCase，如 `MetaExtCustomHeaderSupport` |

- 编号与 `Docs/Issue/` **共用一套计数**：外发后移动到 `Docs/Issue/` 时**编号保持不变**，不重新编号。
- 新增前先核对已用编号（两个目录一起算），以下命令应输出空：

  ```bash
  ls Docs/Issue Docs/Issue/Outside 2>/dev/null | grep -E '^ISSUE-O-[0-9]{4}-' | cut -d- -f3 | sort | uniq -d
  ```

- 当前已用：`0001`；下一个可用：`0002`。

## 3. 外发流程

1. 在 `Outside/` 起草并补齐必备结构（状态栏、问题陈述、现状核对、期望方案、验收标准、待确认决策点）；
2. 提交上游 Issue，拿到链接后把链接写进文首状态栏；
3. 脱敏（去掉 IP / 账号 / 内网域名 / 生产数据），**连同编号**移动到 `Docs/Issue/`；
4. 在 `Docs/CHANGELOG.md` 按 `DocSpec.md` §4 记一条；
5. 上游修复后回填「落地回填」小节：上游版本号 + 本仓库替换提交。

## 4. 风险提示

- 本目录**没有版本历史**：误删、误改无法从 git 恢复。重要草稿请自行备份或定期同步到私有仓库。
- 本目录内容**不得**直接粘贴到公开渠道，外发前必须脱敏。
- 本目录**只有 `README.md` 入库**；其它文件若也需入库（如共享说明），在 `.gitignore` 追加对应白名单（`!Docs/Issue/Outside/文件名`）并说明理由——注意白名单必须写在 `Docs/Issue/Outside/*` 之后才生效。
