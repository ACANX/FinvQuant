## 1. 页面职责

签发与维护 `open.open_api_credential`（一行 = 一种认证模式的密钥）。
调用方列表通过 `GET /Client/Page` 只读加载，用于下拉选择与筛选，不在此页修改。

## 2. 列表

- 查询：调用方下拉（含「全部调用方」）+ 关键字（凭证号 / 公开标识）+ **状态**下拉 + 分页。
- **状态过滤（需求 11217）**：`仅有效[active]`（默认，未吊销/未停用/未过期）/ `全部（含吊销/停用/过期）[all]`；
  默认打开不展示失效凭证，需要追溯时切到「全部」再查询。
- 签发对话框的认证模式支持三种：静态 Key（APIKEY）/ AK-SK 签名（AKSK）/ **STS 兑换凭证（STS，需求 11210）**。
- **STS 兑换凭证**：签发的同样是 `AK_LIVE_` / `SK_LIVE_`，但这对 AK/SK 不能直接调业务接口，
  只能调 `POST /OpenAPI/V1/Meta/Auth/Credential/STS/Issue` 换 2 小时有效的 SAK/SSK/SST；
  填写的授权范围是**派生出的临时凭据**的权限（留空 = 全部接口），IP 白名单与调用方限流同样继承给临时凭据。
  兑换凭证本身长期有效（可设到期日），不需要每次使用都来平台签发。
- 三类凭证互不越权：`AKSK` 不能换临时凭据；兑换凭证不能直连业务；临时凭据不能再换证。被拒都是 `403/19009`。
- 列：IDN、凭证号、调用方、认证模式（静态 Key / AK-SK / STS）、公开标识、授权范围、状态、**到期日期**、最近使用、累计调用、操作。
- **到期日期**：只显示日期；空 = 长期有效；已过期追加「（已过期）」。
- **最近使用 / 累计调用**（`dt_last_use` / `count_use`）：由中间件在**放行**时随审计写入同批更新（`UPDATE ... SET dt_last_use = now(), count_use = count_use + 1`），需求 11199。拒绝的请求不计数；
  每次调用累计到**本次使用的凭证行**（STS 临时凭据计它自己，不再累计到父凭证，需求 11210）；
  兼容兜底密钥（无凭证行）不计数。轮换密钥会把这两列重置为 `NULL` / `0`。
- 公开标识只显示 `key_prefix…`，完整值放在 ⓘ 悬浮里；**密钥材料永不回显**（只有 `has_secret` 布尔）。
- 授权范围显示条数，明细在 ⓘ 悬浮里逐条列出；空 = 全部接口。

## 3. 签发（对话框，两步走）

1. 表单：调用方、凭证号、认证模式、授权范围（每行「方法 路径」）、IP 白名单、到期、备注；
2. 提交后同框切成「密钥展示」步骤：给出 AK（静态 Key 模式即静态 Key 本身）与 SK，
   各自带复制按钮，并提示「关闭后不再显示，丢失只能轮换」。

模式差异：

| 模式 | 返回 | 库内存储 |
|---|---|---|
| 静态 API Key | `SA_LIVE_` + 32 位大写随机（`access_key` = `secret_key`） | `secret_hash`（sha256） |
| AK/SK | AK `AK_LIVE_` + 32 位大写随机、SK `SK_LIVE_` + 48 位大写随机 | `secret_cipher`（AES-256-GCM，密钥取 `sys_config` 19005） |

**大小写（需求 11176）**：凭证号、静态 Key、AK、SK 的英文字母一律大写；凭证号输入框会自动转大写，
服务端入库前也会 `ToUpper`。调用方手写小写时，服务端按大写归一后查库与比对，因此不会因为大小写失败。

`19005` 未配置时签发 AK/SK 返回 503，页面会提示先去系统配置填写。

## 4. 状态操作

| 操作 | 语义 |
|---|---|
| 停用 / 启用 | 可逆，不换密钥；已吊销的凭证不能启用（409） |
| 轮换 | 生成新密钥并**立即**让旧密钥失效（AK/SK 的旧 SK 在签名时间窗内仍可验签） |
| 吊销 | **不可逆**，必须填原因，留 `dt_revoke` + `reason_revoke`；之后只能新建凭证 |

## 5. 说明卡片要点（页面底部）

两种模式的密钥形态与存储方式、状态语义（停用可逆 / 吊销不可逆）、轮换的旧密钥窗口、
授权范围的写法（方法与路径、`/*` 前缀匹配）。

## 7. 授权范围的填写方式（需求 11224）

签发凭证时「授权接口」是**下拉多选**（不再是手敲路径），选项来自
「开放平台 → 安全设置 → OpenAPI 接口清单」里 `flag_public='1'` 且启用中、未下线的接口。

| 场景 | 怎么填 |
|---|---|
| 单点接口授权 | 下拉勾选即可（值 = `方法 路径`，如 `GET /OpenAPI/V1/.../PageUni`） |
| 通配授权 | 下拉选不到，用下方「补充规则」手输，如 `GET /OpenAPI/V1/Meta/Finv/Quote/Cdeu/*` |
| 全部接口 | 两处都留空（仅非静态 Key 模式允许） |

两层合并后去重提交；界面会显示「已选 N 个 + 手输补充 = 合计 M 条规则」。

**静态 Key 只能选 1 个接口**：多选时自动只保留最后一次选择并给出提示（后端同样会校验），
这是 11188 的收紧约束，不是前端限制。

> 为什么不保留纯手输：手敲路径打错一个字符就是「授权了但不生效」，而路径校验只看非空，
> 页面看不出错。下拉选的是清单里的真实路径，从源头避免这类问题；通配规则无法枚举，只能手输。

### 7.1 事后改授权范围（需求 11230）

列表「操作」列的**「授权范围」**按钮可修改已有凭证的范围，不必重新签发：

- 打开时会把现有规则拆成两堆——能对上接口清单的进下拉（已勾选），对不上的（通配/历史值）填进「补充规则」；
- 提交走 `POST /Credential/Scope`，**立即生效**（服务端会让鉴权缓存失效，不用等 10 秒 TTL）；
- 只改范围，不动密钥、IP 白名单、有效期；已吊销凭证不给改（只能新建）；
- 静态 Key 仍是「1 个具体接口、不许通配、不许留空」。
