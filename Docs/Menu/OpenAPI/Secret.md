## 1. 为什么单独一页

`sys.sys_config` 19005 是 **AES-256-GCM 密钥（32 字节，Base64 编码）**：

- 手写 Base64 极易写错（长度差 1 字节就报「必须是 32 字节」）；
- 换密钥会让已签发的 AK/SK 凭证**解不开密文**，必须连带重加密，这不是「随便改个配置字符串」的事。

所以给它单独一页：能一键生成、能备份、能轮换并自动重加密、能配兜底密钥。

## 2. 页面内容

顶部状态 chips：`19004` KID、`19005` 是否已配置、`19006` 是否已配置、持密文凭证数、
「KID 不一致待重加密」数（>0 时红色提示）。

可操作项：

| 控件 | 配置号 | 说明 |
|---|---|---|
| 密钥版本 KID | 19004 | 字母/数字/`._-`，1~16 位；换钥时建议递增（`k1` → `k2`） |
| 新的加密密钥 | 19005 | Base64（32 字节）；**留空表示不修改**；点「生成 32 字节密钥」用浏览器 `crypto.getRandomValues` 生成并填入，可复制备份 |
| 重加密现有凭证 | — | 换钥时默认勾选；勾选后在**同一个事务**里用旧密钥解、新密钥加密、更新 `secret_kid` |
| 兼容兜底静态密钥 | 19006 | 留空不改；可勾「清空兜底密钥」 |

底部说明卡片解释：19005 的用途与必须备份、密钥在浏览器本地生成、换钥必须重加密（否则 `19010`）、
KID 的作用、19006 的过渡定位、静态 Key 不依赖 19005。

## 3. 保存规则

- 三项都「空 = 不改」，因此想清空兜底密钥要勾选复选框（空串无法与「不改」区分）。
- 换密钥且未勾选重加密时，前端会二次确认并明确说明后果（旧凭证 AK/SK 调用返回 `19010`）。
- 保存后 10 秒内生效（进程内短 TTL 缓存），不需要重启服务。
- 若有凭证的旧密文连旧密钥也解不开（历史遗留），服务端**跳过并计数**，页面会提示
  「N 条凭证的旧密文解不开，请重新签发这些凭证」。

## 4. 与其它页面的分工

| 页面 | 管什么 |
|---|---|
| OpenAPI 鉴权配置 | 19001 模式 / 19002 时间窗 / 19003 日志保留天数；只读显示密钥是否已配置 |
| **OpenAPI 密钥配置** | 19004 KID / 19005 加密密钥 / 19006 兜底密钥（本页） |
| OpenAPI 凭证 | 签发/轮换/停用/吊销凭证（用到 19005 加密） |
