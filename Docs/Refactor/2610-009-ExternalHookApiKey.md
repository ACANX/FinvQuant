# 外部 HOOK 接入：API Key 认证方案

> 状态：**方案草案（待评审，未实施）**
> 日期：2026-10-28
> 关联：认证实现（需求 10761）、路由 [`internal/api/router.go`](../../internal/api/router.go)、
> 会话存储 [`internal/meta/finv/auth/session.go`](../../internal/meta/finv/auth/session.go)
> 目标读者：后端、运维、外部接入方

## 1. 背景与问题

外部系统（行情采集端、TradingView / 券商 / 内部定时任务等 HOOK）需要调用部分 API 写入或读取数据。
加入登录功能后，除健康检查/版本/登录外的全部业务接口都挂在 `apiGroup` 上，由
`RequireAuth` 校验 `Authorization: Bearer <会话令牌>`：

- 会话令牌是登录后写入 Redis 的 32 字节随机串，**8 小时 TTL 且滑动续期**（配置 20012）；
- 改密/登出会立即吊销该用户全部会话；
- 外部 HOOK 无法交互式登录，也不应持有用户口令。

因此需要为**非交互式调用方**提供独立的机器凭证，同时不降低现有 Web 会话的安全性。

## 2. 现状

### 2.1 认证机制

| 项 | 现状 |
|---|---|
| 用户口令 | `sys.sys_user`，argon2id 哈希 + salt |
| 会话令牌 | 登录生成 32 字节随机 hex，存 Redis `finv:auth:session:<token>` |
| 有效期 | 默认 8h，读 `sys_config 20012`，每次 `Resolve` 滑动续期 |
| 注销 | `Logout` 删除会话；改密删除该用户全部会话 |
| 传递方式 | `Authorization: Bearer <token>` |
| 路由保护 | `/API/V1` 业务组统一 `RequireAuth`；仅 Health/Version/Login 公开 |

### 2.2 为什么不能复用登录令牌

| 问题 | 说明 |
|---|---|
| 会过期 | 8h 后失效，HOOK 需要实现登录 + 刷新，复杂度转移到外部 |
| 需存口令 | 外部系统必须保存用户明文口令，泄露面扩大 |
| 权限过大 | 会话继承用户全部权限，无法按 HOOK 最小授权 |
| 审计混淆 | 会话审计区分不出「人」与「机器」 |
| 牵连影响 | 用户改密/登出会误伤 HOOK |

## 3. 目标与非目标

**目标**

1. 外部 HOOK 使用独立凭证调用，无需登录、不过期（或长有效期）且可随时吊销；
2. 凭证可按**端点/业务域**授权（最小权限），并可按来源 IP 限制；
3. 不改变现有 Web 登录与路由行为；
4. 凭证可审计（谁、何时、从哪个 IP、调了什么、结果）；
5. 可限流，避免异常调用拖垮服务。

**非目标（本期不做）**

- OAuth2 / OIDC 授权服务器；
- 按请求体内容做细粒度授权（如只允许写某只证券）；
- 多租户配额计费。

## 4. 方案对比

| 方案 | 安全性 | 实现量 | 优点 | 缺点 |
|---|---|---|---|---|
| **A. API Key + 独立 Hook 路由组** | 中高 | 小 | 简单、可吊销、可 scope/限流 | 凭证泄露即等效授权（需 HTTPS + 轮换） |
| B. A + HMAC 签名 | 高 | 中 | 防重放/防篡改 | HOOK 侧实现复杂；服务端需保存可校验的 secret |
| C. 固定 Token + IP 白名单 | 中 | 最小 | 当天可上线 | 单凭证、难轮换、多 HOOK 不可区分 |
| D. HOOK 系统账号走登录 | 低 | 小 | 无新代码 | 令牌过期、存口令、权限过大 |

**推荐：A**；公网 HOOK 或高价值写入场景叠加 B。

## 5. 推荐方案设计（A）

### 5.1 总体流程

```text
外部 HOOK ──(Authorization: Bearer fq_xxx / X-API-Key: fq_xxx)──▶ Nginx ──▶ FinvQuant
                                                                          │
                                            RequireAPIKey（Hook 路由组专用）
                                                                          │
                                    校验 hash/enabled/expires/scope/IP → 限流 → handler
```

关键点：

- Hook 路由组**独立**（如 `/API/V1/Hook/...`），只挂 `RequireAPIKey`；
- 现有 `/API/V1/Meta/Finv/...` 继续挂 `RequireAuth`，两套凭证互不通用；
- handler 复用，不复制业务逻辑。

### 5.2 凭据格式

```text
fq_<8位公开前缀>_<64位随机hex>
示例：fq_7a3c9b21_5f1e...（共 77 字符）
```

- 前缀用于日志/界面识别与快速检索，**不是秘密**；
- 数据库只存 `sha256(完整 key)`（`BYTEA`），不存明文；
- 明文仅在创建响应中返回一次，丢失只能吊销重建；
- 有效期默认 **180 天**（决策点 6），创建时可显式设为长期（`expires_at = NULL`）；
- 一个 key 可同时授予多个 scope（决策点 12），如 `{kline:write,kline:read}`。

### 5.3 数据模型（DDL 草案）

```sql
-- 迁移编号待定（建议 V200058+；以实际最大编号为准）
CREATE TABLE IF NOT EXISTS sys.sys_open_api_key (
    idn            bigint       GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name           varchar(64)  NOT NULL,              -- 用途，如 tradingview-hook
    key_prefix     varchar(16)  NOT NULL,              -- 公开前缀，如 fq_7a3c9b21
    key_hash       bytea        NOT NULL,              -- sha256(完整 key)
    scopes         text[]       NOT NULL DEFAULT '{}', -- 如 {kline:write,kline:read}
    ip_allow       text[]       NOT NULL DEFAULT '{}', -- CIDR；空=不限制（见决策点）
    enabled        boolean      NOT NULL DEFAULT true,
    -- 默认 180 天过期；创建时显式传 NULL 表示长期有效（决策点 6）
    expires_at     timestamptz  DEFAULT (now() + interval '180 days'),
    rate_limit_per_min integer,                        -- NULL=使用全局默认（决策点 7）
    last_used_at   timestamptz,
    description    text,
    created_by     bigint       REFERENCES sys.sys_user(idn),
    gmt_create     timestamptz  NOT NULL DEFAULT now(),
    gmt_update     timestamptz  NOT NULL DEFAULT now(),
    CONSTRAINT uq_sys_open_api_key_prefix UNIQUE (key_prefix)
);
CREATE INDEX IF NOT EXISTS idx_sys_open_api_key_enabled ON sys.sys_open_api_key (enabled) WHERE enabled;

-- 可选：调用审计表（也可先只写日志）
CREATE TABLE IF NOT EXISTS sys.sys_open_api_key_call_log (
    idn          bigint      GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    api_key_idn  bigint      NOT NULL REFERENCES sys.sys_open_api_key(idn),
    method       varchar(8)  NOT NULL,
    path         varchar(255) NOT NULL,
    status       integer     NOT NULL,
    client_ip    inet,
    duration_ms  integer,
    gmt_create   timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS idx_sys_open_api_key_call_log_key_time
    ON sys.sys_open_api_key_call_log (api_key_idn, gmt_create DESC);
```

> 表归属 `sys.`（系统域），与 `sys_user` 一致；命名/字段风格（`idn`、`gmt_create/gmt_update`）对齐现有规范。

### 5.4 校验流程与中间件

```go
// 伪代码：internal/apikey + internal/api/middleware.go
func RequireAPIKey(store *apikey.Store, needScope string) gin.HandlerFunc {
    return func(c *gin.Context) {
        raw := apiKeyFromRequest(c)          // Authorization: Bearer 或 X-API-Key
        if raw == "" { abortUnauthorized(c); return }

        key, err := store.Verify(c.Request.Context(), raw, needScope, c.ClientIP())
        if err != nil { abortUnauthorized(c); return }

        c.Set(apikey.ContextKeyKeyID, key.IDN)
        c.Next()
    }
}

// Store.Verify 内部顺序：
// 1) 解析前缀 → 查缓存/DB（按 key_prefix）
// 2) subtle.ConstantTimeCompare(sha256(raw), key_hash)
// 3) enabled && (expires_at 为空或未过期)
// 4) scope 包含 needScope
// 5) ip_allow 为空或 ClientIP 命中 CIDR
// 6) last_used_at 节流更新（如 >60s 才写）
```

- 前缀查询：`key_prefix` 唯一索引；可加 Redis 短缓存（60s），吊销时主动删缓存；
- 401 响应不复用 KLine 错误码（认证域独立）；响应体不提示“前缀存在但 hash 错误”。

### 5.6 管理接口（仅登录用户）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/API/V1/Meta/Finv/Auth/APIKey` | 创建，响应仅此一次返回明文 key |
| GET | `/API/V1/Meta/Finv/Auth/APIKey/List` | 列表（只显示前缀/名称/scope/状态/最后使用） |
| PATCH | `/API/V1/Meta/Finv/Auth/APIKey/{idn}` | 改名称/scope/IP/启停 |
| DELETE | `/API/V1/Meta/Finv/Auth/APIKey/{idn}` | 吊销（软删或 `enabled=false`） |

权限（决策点 9）：**本期不做控制**——所有已登录用户均可调用管理接口；按角色/scope 细分列为后续待决策事项（见 §8.1）。

### 5.7 限流（草案）

- 维度：`api_key_idn` + 固定窗口（每分钟）；
- Redis：`INCR finv:apikey:rate:<idn>:<epochMinute>`，`EXPIRE 120`；
- 超限返回 `429`，响应头 `Retry-After`；
- 阈值：全局默认 60 req/min；每个 key 可用 `rate_limit_per_min` 覆盖（决策点 7），
  为 `NULL` 时使用全局默认；调整无需重启（读缓存/表字段）。

### 5.8 审计日志

- 每次请求记录：`api_key_idn`、`method`、`path`、`status`、`client_ip`、`duration_ms`；
- **不记录**请求体与响应体（K 线数据量大且含业务数据）；如需，另设开关；
- 失败（401/403/429）单独告警阈值（可选）。

### 5.9 配置项（草案）

```env
FINV_APIKEY_ENABLED=true           # 关闭时 Hook 路由组不注册（404）
FINV_APIKEY_RATE_LIMIT=60          # 默认每分钟上限
FINV_APIKEY_CACHE_TTL=60s          # 前缀→key 缓存
FINV_APIKEY_TRUST_PROXY=false      # 是否信任 X-Forwarded-For（Nginx 后置 true）
```

### 5.10 安全设计

| 风险 | 措施 |
|---|---|
| 凭证泄露 | 只存 hash；创建后不可再读；支持吊销与过期；建议 90 天轮换 |
| 传输窃听 | 强制 HTTPS（Nginx 443）；HTTP 仅限内网 |
| 重放 | 方案 A 依赖 HTTPS；高安全场景叠加 HMAC + timestamp/nonce（方案 B） |
| 暴力猜测 | 64 hex 随机 + 限流 + 失败告警 |
| 越权 | scope 白名单 + 独立 Hook 路由组，不挂 Web 业务组 |
| 审计缺失 | `sys_open_api_key_call_log` + 结构化日志 |

### 5.11 运维流程

1. 登录 → 「API Key 管理」创建（选择 scope、IP、有效期、限流）；
2. 复制明文 key 配置到 HOOK（只显示一次）；
3. 轮换：创建新 key → 切换 HOOK → 观察 `last_used_at` → 吊销旧 key；
4. 泄露：立即吊销（`enabled=false`）+ 查审计日志。

## 6. 可选增强（方案 B：HMAC 签名）

适用于公网 HOOK。请求头：

```text
X-Fq-Key-Id: fq_7a3c9b21
X-Fq-Timestamp: 1792695045
X-Fq-Nonce: 8f3c1d2e...
X-Fq-Signature: <hex(HMAC-SHA256(secret, method + "\n" + path + "\n" + timestamp + "\n" + nonce + "\n" + hex(sha256(body))))>
```

服务端校验：时间窗 ±300s、nonce 未使用（Redis `SET NX EX 600`）、常量时间比较。
需要服务端保存可用的 `secret`（加密存储或 KMS），因此**不建议默认开启**。

## 7. 兼容性与迁移

- 纯新增：新表、新中间件、新路由组、新管理接口；**不修改**现有 `RequireAuth` 与业务路由；
- 未创建 API Key 时 Hook 路由组仍注册但全部 401（或按配置整体 404）；
- 前端新增「API Key 管理」菜单（可后置）；
- 迁移编号取 `Deploy/Migrations` 当前最大值 +1（种子类走 `V200xxx`）。

## 9. 验收标准

```bash
# 1) 未带凭证 → 401
curl -s -o /dev/null -w '%{http_code}\n' -X POST \
  http://127.0.0.1:16001/API/V1/Hook/Quote/Cdeu/Min/Upsert   # 401

# 2) 有效 key + 正确 scope → 200
curl -s -o /dev/null -w '%{http_code}\n' -X POST \
  -H 'Authorization: Bearer fq_xxx' -H 'Content-Type: application/json' \
  -d '{"items":[]}' \
  http://127.0.0.1:16001/API/V1/Hook/Quote/Cdeu/Min/Upsert   # 400/200（按业务校验）

# 3) Web 业务路由仍要求登录
curl -s -o /dev/null -w '%{http_code}\n' \
  http://127.0.0.1:16001/API/V1/Meta/Finv/Quote/Cdeu/Min/Count  # 401

# 4) 吊销后立即 401；5) 超限 429；6) scope 不足 403

# 7) 一个 key 授予多个 scope 后可同时调用读写端点
#    scopes = {kline:write,kline:read} → Upsert 与 Query 均返回非 401/403

# 8) 默认有效期为 180 天（创建时未显式指定）
sudo -u postgres psql -d finv -tAc \
  "select expires_at > now() + interval '179 days' from sys.sys_open_api_key where idn = <idn>"
```

- 迁移 `schema_version` 记录成功；
- 审计表有对应记录；

## 11. 风险与回滚

| 风险 | 缓解 | 回滚 |
|---|---|---|
| Hook 路由误开放写接口 | 默认只读 + 显式勾选 scope | 移除路由注册 |
| 凭证泄露 | hash 存储、轮换、吊销、审计 | 吊销全部 key |
| 限流误伤 | 可配置阈值 + 白名单 key | 关闭限流开关 |
| 表结构变更 | 纯新增表，不影响现有查询 | 保留表，停用路由 |
