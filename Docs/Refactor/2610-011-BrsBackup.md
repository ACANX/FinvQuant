## 1. 背景与目标

远端服务器存在被回收的风险，需要每日备份重要数据。首期只做 **PostgreSQL 表级备份**，
稳定后再扩展配置文件备份与自动恢复。

**最终目标**：备份产物上传到 **S3 兼容对象存储**（Cloudflare R2 / AWS S3 / MinIO /
Backblaze B2 / 阿里云 OSS 等），便于异地留存与下载恢复。

**首期目标**

1. 新增 `brs` schema 与备份登记表；
2. 服务内定时任务，每日按登记表 `priority` 倒序备份；
3. 使用 `pg_dump` 表级备份，快速、高压缩；
4. 只写日志，暂不建运行记录表；
5. 不备份大表 `cdeu.finv_quote_secu_kline_min`（后续单独方案）。

## 2. 设计决策（已确认）

| # | 决策点 | 结果 |
|---|---|---|
| 1 | 定时实现 | 服务内定时任务（非独立进程） |
| 2 | cron | **6 段**（秒 分 时 日 月 周），实现于 `internal/meta/base/cron`（手写解析、独立包，后续可抽出单独库） |
| 3 | cron 配置 | `sys.sys_config` **39001**（`str_value`，如 `0 0 3 * * *`） |
| 4 | 备份方式 | 默认 **`pg_dump`** 表级 |
| 5 | 压缩 | 快速 + 高压缩比：`zstd`（默认 `zstd:3`），可选 `gzip`/`none` |
| 6 | 开关 | `flag_enable char(1)`：`'1'` 启用 / `'0'` 停用 |
| 7 | creator | 存 `sys_user.uid`（varchar） |
| 8 | 运行记录 | 首期只写日志，不建 job/item 表 |
| 9 | 种子 | 预置系统表与 CDEU 配置表；**不含** `cdeu.finv_quote_secu_kline_min` |
| 10 | 最终目标 | 上传 S3 兼容对象存储（二期） |

## 3. 表结构设计

### 3.1 `brs.brs_bak_rdb_table`

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `idn` | bigint identity | — | 主键 |
| `rdb_type` | varchar(32) | `postgresql` | 数据库类型 |
| `schema_name` | varchar(64) | — | schema（避开保留字 `schema`） |
| `table_name` | varchar(128) | — | 表名 |
| `flag_enable` | char(1) | `'1'` | `'1'` 启用 / `'0'` 停用 |
| `priority` | integer | — | 执行优先级：**必填且值唯一**，越大越先执行 |
| `bak_scope` | varchar(16) | `both` | `both` / `schema` / `data` |
| `bak_method` | varchar(16) | `pg_dump` | 首期固定 `pg_dump` |
| `compression` | varchar(16) | `zstd` | `none` / `gzip` / `zstd` |
| `where_clause` | text | NULL | 预留（`pg_dump` 模式暂不生效） |
| `remark` | text | NULL | 备注 |
| `creator` | varchar(32) | NULL | 创建人 `sys_user.uid` |
| `gmt_create` | timestamptz | `now()` | 创建时间 |
| `gmt_update` | timestamptz | `now()` | 修改时间（触发器维护） |

约束：

- `PRIMARY KEY (idn)`
- `UNIQUE (rdb_type, schema_name, table_name)`
- `CHECK (flag_enable IN ('0','1'))`
- `UNIQUE (priority)`（优先级值唯一）
- `CHECK (priority >= 0)`
- `CHECK (bak_scope IN ('both','schema','data'))`
- `CHECK (bak_method IN ('pg_dump','copy'))`
- `CHECK (compression IN ('none','gzip','zstd'))`

### 3.2 DDL 草案（批准后写入迁移）

```sql
CREATE SCHEMA IF NOT EXISTS brs;

CREATE TABLE brs.brs_bak_rdb_table (
    idn            bigint       GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY, -- 主键
    rdb_type       varchar(32)  NOT NULL DEFAULT 'postgresql',                -- 数据库类型（首期 postgresql）
    schema_name    varchar(64)  NOT NULL,                                     -- schema 名（避开保留字 schema）
    table_name     varchar(128) NOT NULL,                                     -- 表名
    flag_enable    char(1)      NOT NULL DEFAULT '1',                         -- 备份开关：1 启用 / 0 停用
    priority       integer      NOT NULL,                                     -- 执行优先级，越大越先（值唯一）
    bak_scope      varchar(16)  NOT NULL DEFAULT 'both',                      -- 备份范围：both / schema / data
    bak_method     varchar(16)  NOT NULL DEFAULT 'pg_dump',                   -- 备份方式：首期 pg_dump
    compression    varchar(16)  NOT NULL DEFAULT 'zstd',                      -- 压缩：none / gzip / zstd
    where_clause   text,                                                      -- 预留：部分数据备份条件
    remark         text,                                                      -- 备注
    creator        varchar(32),                                               -- 创建人（sys_user.uid）
    gmt_create     timestamptz  NOT NULL DEFAULT now(),                       -- 创建时间
    gmt_update     timestamptz  NOT NULL DEFAULT now(),                       -- 修改时间（触发器维护）
    CONSTRAINT uq_brs_bak_rdb_table UNIQUE (rdb_type, schema_name, table_name), -- 同一库内表唯一
    CONSTRAINT uq_brs_bak_rdb_table_priority UNIQUE (priority),                  -- 优先级值唯一
    CONSTRAINT ck_brs_bak_rdb_table_flag CHECK (flag_enable IN ('0', '1')),     -- 开关取值
    CONSTRAINT ck_brs_bak_rdb_table_priority CHECK (priority >= 0),             -- 优先级非负
    CONSTRAINT ck_brs_bak_rdb_table_scope CHECK (bak_scope IN ('both', 'schema', 'data')), -- 范围取值
    CONSTRAINT ck_brs_bak_rdb_table_method CHECK (bak_method IN ('pg_dump', 'copy')),      -- 方式取值
    CONSTRAINT ck_brs_bak_rdb_table_compression CHECK (compression IN ('none', 'gzip', 'zstd')) -- 压缩取值
);
```

## 4. 定时与 cron

### 4.1 配置 39001

`sys.sys_config`：`config_no=39001`，`data_type='3'`，`str_value` 为 6 段 cron：

```text
秒 分 时 日 月 周
0  0  3  *  *  *   # 每天 03:00:00
```

周 `0-6`（0=周日）；支持 `*`、`?`（仅日/周）、数字、`a-b`、`*/n`、`a-b/n`、列表。
修改后最多 60 秒生效；非法表达式只记日志。

### 4.2 `internal/meta/base/cron` 独立包

- 仅依赖标准库，后续可抽出为单独库；
- API：`Parse(expr) (*Schedule, error)`、`(*Schedule).Matches(t time.Time) bool`、
  `(*Schedule).Next(t time.Time) time.Time`；
- 日与周同时指定时按“同时满足”处理（通常用 `?` 忽略一个）。

## 5. 备份执行流程

1. 服务启动时 `go brs.Start(ctx, pool, opts)`；
2. 每秒检查 39001 cron，命中则执行一轮；
3. 读取 `brs.brs_bak_rdb_table`（`flag_enable='1'`，`priority DESC`）；
4. 逐表执行：

   ```bash
   pg_dump --host <h> --port <p> --username <u> --dbname <db> \
     --table=<schema>.<table> --format=custom \
     --compress=zstd:3 --file=<out>
   ```

   - `bak_scope=schema` → `--schema-only`；`data` → `--data-only`；
   - `compression=none` → `--compress=none`；`gzip` → `gzip:6`；
5. 文件：`<PREFIX>/Backup/BRS/<yyyyMMdd>/<schema>.<table>_<HHmmss>.dump`；
6. 失败继续下一张表，最后汇总日志；
7. 单表超时 30 分钟；`PGPASSWORD` 只通过子进程环境传递。

日志前缀 `[brs]`，写入 `Log/FinvQuant.log` 与 journald。

## 6. S3 兼容对象存储（二期）

### 6.1 客户端选型（规避 MinIO 依赖）

> 背景：MinIO 开源策略调整，**不使用 `minio-go` 及任何 MinIO 官方库**。

| 方案 | 说明 | 结论 |
|---|---|---|
| `aws-sdk-go-v2/service/s3` | AWS 官方 S3 SDK，SigV4；R2 / S3 / MinIO / B2 / OSS 均兼容 | **默认适配器** |
| 自研最小 S3 客户端（SigV4 + HTTP） | 依赖最少，但需自行维护签名/分片/重试 | 备选（SDK 依赖不可接受时） |
| 厂商专用 SDK（OSS/COS 等） | 与厂商绑定 | 不采用 |

### 6.2 协议抽象层（避免被单一客户端/厂商绑死）

新增独立包 `internal/meta/base/oss`，业务层只依赖接口，不直接引用任何 SDK：

```go
// internal/meta/base/oss
type ObjectInfo struct {
    Key          string
    Size         int64
    ETag         string
    LastModified time.Time
}

type Store interface {
    Put(ctx context.Context, key string, body io.Reader, size int64, contentType string) error
    Get(ctx context.Context, key string) (io.ReadCloser, error)
    Stat(ctx context.Context, key string) (ObjectInfo, error)
    Delete(ctx context.Context, key string) error
}

type Config struct {
    Provider  string // s3 / local / oss ...
    Endpoint  string
    Bucket    string
    Region    string
    AccessKey string
    SecretKey string
    Prefix    string
}

// New 按 Provider 返回实现；未知 Provider 返回错误。
func New(cfg Config) (Store, error)
```

- 适配器放在子包，SDK 依赖被隔离：
  - `internal/meta/base/oss/s3`：基于 `aws-sdk-go-v2/service/s3`；
  - `internal/meta/base/oss/local`：本地目录（单测/离线环境）；
  - 后续新增 `oss`/`cos` 等只加适配器；
- BRS 业务代码只调用 `Store.Put/Get/Stat/Delete`，**切换客户端/厂商时只改 `New` 的配置与适配器**，不改业务；
- 契约测试：用 `local`/内存 stub 对 `Store` 接口做一致性测试，S3 适配器另做可选集成测试。

### 6.3 上传配置（`sys.sys_config 39002`，JSON）

```json
{
  "enabled": true,
  "provider": "s3",
  "endpoint": "https://<account>.r2.cloudflarestorage.com",
  "bucket": "finvquant-backup",
  "region": "auto",
  "access_key": "...",
  "secret_key": "...",
  "prefix": "brs/"
}
```

| 项 | 方案 |
|---|---|
| 开关 | 全局 39002 `enabled` + 表级 `flag_upload`（`'1'/'0'`，默认 `'1'`） |
| 上传 key | `<prefix>/<yyyyMMdd>/<schema>.<table>_<HHmmss>.dump` |
| 校验 | ETag / SHA256（`.sha256` 一并上传） |
| 失败 | 保留本地文件，重试 3 次；不影响下一张表 |
| 下载恢复 | 任意 S3 兼容 CLI（`aws s3 cp` / `rclone` 等）下载 → `pg_restore`，不限定厂商工具 |
| 安全 | access/secret 存 `sys_config`（`access_level` 限制），不写日志 |

## 8. 验收标准

```sql
-- 迁移后
select count(*) from brs.brs_bak_rdb_table;              -- 12

```

- 备份目录出现 `<schema>.<table>_<HHmmss>.dump`；
- `pg_restore -l` 可列出内容；
- 单表失败不影响其它表；
- `go test ./internal/meta/base/cron ./internal/brs`、`go build ./...` 通过。

## 9. 风险与后续

| 风险 | 缓解 |
