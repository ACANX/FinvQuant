# 错误码规范（ErrorCodeSpec）

> 所属：FinvQuant 开发规范 · 存放：`Docs/DevSpec/`
> 适用范围：VeritasQuant 全部业务错误码的定义、号段与目录管理。
> 依据：技术方案（TechSpec）第 10.2 节；API 响应形态见 [`ApiSpec.md`](ApiSpec.md)。

## 1. 号段规划

- 成功码集合固定为 `{0, 1, 200, 202}`；除固定成功码外，`2-999` 仅允许显式注册为非错误业务状态。
- `1000-2999` 为平台、安全和依赖错误。
- **项目自定义业务错误码必须大于或等于 3000**，并严格遵循技术方案第 10.2 节的领域号段与后三位分类。

## 1.1 FinvQuant 实际号段（2026-10-24 起）

| 号段 | 用途 | 处置 |
|---|---|---|
| `0-3000` | 成功码（`0/1/200/202`）、平台与依赖码（如 `2006`）、原 HTTP 错误码（`400/404/409/413/422/503`） | **沿用/复用**，不得改写 |
| `21xxxx`（自 `211xxx` 起） | 需要向调用方区分具体错误类型的业务错误 | **启用**；子段：`2110xx` 校验、`2111xx` 资源/冲突、`2112xx` 容量、`2113xx` 存储/依赖 |
| `20xxx` | 历史号段（`2006` 等） | **沿用**，不得改写 |
| `190xx`（`19001`～`19099`） | **外部 OpenAPI 鉴权与限流**（认证缺失/凭证无效/签名不符/时间窗/nonce 重放/IP 白名单/授权范围/限流/密钥未配置） | **启用**（需求 11167，2026-11-15 用户指定子段）；目录见下文 §1.2 |
| `>3000` 旧业务号（`4001/4004/4009`） | 历史号段 | **停用**，分别收敛为 `400`/`404`/`211104` |

- 具体错误一律使用 `211xxx`（目录见 `Docs/API/KLine/*.md` 与实现 `internal/meta/finv/quote/cdeu/kline/apierr.go`），编号全局唯一、语义不复用。
- 无法归类到具体码的错误，`code` 回退为 HTTP 状态码（`500` 沿用 `2006`）。
- 新增/调整具体码必须同步：实现目录、接口文档、契约测试（号段 + HTTP 映射 + 唯一性）。
- **`190xx` 与 `211xxx` 的关系**：`211xxx` 面向**内部业务接口**（登录会话体系），`190xx` 专供**外部 OpenAPI**（`/OpenAPI/V1`，API Key / AK-SK 体系）。两段互不复用，调用方按响应 `code` 就能区分「是我签名错了」还是「平台业务出错」。

### 1.2 外部 OpenAPI 鉴权错误码目录（`190xx`，需求 11167）

| 码 | HTTP | 符号 | 含义 | 调用方处置 |
|---|---|---|---|---|
| `19001` | 401 | `OPENAPI_KEY_MISSING` | 未携带任何凭证（既无 `X-API-Key`，也无 `Authorization` 签名头） | 补凭证 |
| `19002` | 401 | `OPENAPI_KEY_INVALID` | 凭证未知或密钥不匹配（静态 Key 哈希不符 / AK 未登记 / SK 验签失败都归这里，**不区分**，避免探测） | 核对 AK 与 SK |
| `19003` | 403 | `OPENAPI_CREDENTIAL_DISABLE` | 凭证已停用、已吊销，或调用方/凭证已过期 | 联系平台方续期或换凭证 |
| `19004` | 401 | `OPENAPI_CIDR_DENY` | 来源 IP 不在（调用方 ∩ 凭证）白名单内 | 换出口 IP 或申请加白 |
| `19005` | 401 | `OPENAPI_SIGN_MISMATCH` | 签名不匹配（AK 已知但重算 HMAC 不等） | 检查待签串拼装（方法/路径/查询串/body 摘要/时间戳/nonce） |
| `19006` | 401 | `OPENAPI_TIMESTAMP_SKEW` | 时间戳超出允许窗口（`sys_config` 19002，默认 ±300 秒） | 校准系统时间 |
| `19007` | 401 | `OPENAPI_NONCE_REPLAY` | nonce 在窗口内重复（重放攻击嫌疑） | 每次请求换新 nonce |
| `19008` | 429 | `OPENAPI_RATE_LIMIT` | 超出速率（每分钟）或每日配额 | 退避重试 |
| `19009` | 403 | `OPENAPI_SCOPE_DENY` | 凭证 `scope_str` 不含该接口 | 申请授权范围 |
| `19010` | 503 | `OPENAPI_NOT_READY` | 平台侧鉴权未就绪（如 19005 加密密钥未配置却收到 AK/SK 请求） | 联系平台方 |

- 以上码是**契约**：`19002` 刻意合并「AK 不存在」与「SK 不匹配」，防止攻击者借错误码差异枚举有效 AK。
- 新增/调整必须同步三处：`internal/api/openapi/*`（实现目录）、`Docs/API/OpenAPI/Auth.md`（接口文档）、`internal/api/openapi/errcode_test.go`（号段 + HTTP 映射 + 唯一性契约测试）。

- **错误详情分级**：默认只输出安全文案（`safe`）；`FINV_ERROR_DETAIL_MODE=admin` 且携带有效 `X-Debug-Token` 或来自 `FINV_ERROR_DETAIL_ALLOWED_CIDRS` 时，才输出白名单 `debug` 字段；DSN、完整 SQL、堆栈、令牌、内部主机名等永不进入响应。

## 2. error 对象

- 所有错误的 `error` 对象必须携带 `code`、`catalog_version` 和 `retryable`。
- 错误响应顶层的 `request_id` **必须是纯大写**：内部接口为大于等于 36 字符的大写 UUID4，
  对外 OpenAPI 鉴权拒绝为 32 位大写十六进制（口径见 [`ApiSpec.md`](ApiSpec.md) §1.0）。

## 3. 错误目录

- 完整统一代码目录固定为 `src/veritasquant/resources/Schemas/ApiErrorCodes.yml`，所有字段使用 **PascalCase**。
- 数值码和符号码全局唯一；已发布号码**不得删除、改变语义或复用于其他错误**。
- 第三方错误必须在**适配器边界**映射。

## 4. 契约测试

错误码契约测试必须覆盖：

- 3000 以上业务码的唯一性和号段归属；
- 目录版本兼容；
- 业务状态注册的合法性。
