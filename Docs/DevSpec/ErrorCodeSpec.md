# 错误码规范（ErrorCodeSpec）

> 所属：FinvQuant 开发规范 · 存放：`Docs/DevSpec/`
> 适用范围：VeritasQuant 全部业务错误码的定义、号段与目录管理。
> 依据：技术方案（TechSpec）第 10.2 节；API 响应形态见 [`ApiSpec.md`](ApiSpec.md)。

## 1. 号段规划

- 成功码集合固定为 `{0, 1, 200, 202}`；除固定成功码外，`2-999` 仅允许显式注册为非错误业务状态。
- `1000-2999` 为平台、安全和依赖错误。
- **项目自定义业务错误码必须大于或等于 3000**，并严格遵循技术方案第 10.2 节的领域号段与后三位分类。

## 1.1 FinvQuant 实际号段（2026-10-24 起）

| 号段 | 用途 | 处置 |
|---|---|---|
| `0-3000` | 成功码（`0/1/200/202`）、平台与依赖码（如 `2006`）、原 HTTP 错误码（`400/404/409/413/422/503`） | **沿用/复用**，不得改写 |
| `21xxxx`（自 `211xxx` 起） | 需要向调用方区分具体错误类型的业务错误 | **启用**；子段：`2110xx` 校验、`2111xx` 资源/冲突、`2112xx` 容量、`2113xx` 存储/依赖 |
| `>3000` 旧业务号（`4001/4004/4009`） | 历史号段 | **停用**，分别收敛为 `400`/`404`/`211104` |

- 具体错误一律使用 `211xxx`（目录见 `Docs/API/KLine/*.md` 与实现 `internal/meta/finv/quote/cdeu/kline/apierr.go`），编号全局唯一、语义不复用。
- 无法归类到具体码的错误，`code` 回退为 HTTP 状态码（`500` 沿用 `2006`）。
- 新增/调整具体码必须同步：实现目录、接口文档、契约测试（号段 + HTTP 映射 + 唯一性）。
- **错误详情分级**：默认只输出安全文案（`safe`）；`FINV_ERROR_DETAIL_MODE=admin` 且携带有效 `X-Debug-Token` 或来自 `FINV_ERROR_DETAIL_ALLOWED_CIDRS` 时，才输出白名单 `debug` 字段；DSN、完整 SQL、堆栈、令牌、内部主机名等永不进入响应。

## 2. error 对象

- 所有错误的 `error` 对象必须携带 `code`、`catalog_version` 和 `retryable`。

## 3. 错误目录

- 完整统一代码目录固定为 `src/veritasquant/resources/Schemas/ApiErrorCodes.yml`，所有字段使用 **PascalCase**。
- 数值码和符号码全局唯一；已发布号码**不得删除、改变语义或复用于其他错误**。
- 第三方错误必须在**适配器边界**映射。

## 4. 契约测试

错误码契约测试必须覆盖：

- 3000 以上业务码的唯一性和号段归属；
- 目录版本兼容；
- 业务状态注册的合法性。
