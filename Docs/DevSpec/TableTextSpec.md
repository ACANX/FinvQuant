# 表格长文本展示规范（TableTextSpec）

> 所属：FinvQuant 开发规范 · 存放：`Docs/DevSpec/`
> 适用范围：前端（`Web/`）全部业务页面的**表格列**（`v-table` / `v-data-table`）。
> 关联：[`UiSpec.md`](UiSpec.md)（组件与反馈统一）、[`ExplainCardSpec.md`](ExplainCardSpec.md)（静态说明放页面底部「说明」卡片）、[`MenuSpec.md`](MenuSpec.md)（状态列规范）、[`DocSpec.md`](DocSpec.md)（文档与变更日志）。
> 参考实现：`Web/src/views/Meta/Finv/Quote/Realtime/UscMappingView.vue`（「规则」页签与「条目」页签的说明列，需求 11105 / 11107）。

## 1. 目的与结论

**表格单元格里不放整段文字**：说明、备注、依据这类长文本一律收进「ⓘ 图标 + 鼠标悬浮提示」，单元格只留一个图标。

这是本项目的**默认风格**：新增页面/新列按此写；已有页面在改造时逐步迁移，不做一次性全量改写。

一句话规则：

> 一列只放「能比较的短值」；放不下的解释性文字走 ⓘ 悬浮，表格保持等宽紧凑。

### 1.1 为什么（真实案例，不是洁癖）

`/Meta/Finv/Quote/Realtime/UscMapping` 原先把 `rule_desc`（每条规则的整段解释）直接铺在「说明」列：

- 行高被文字撑成 4～6 行，10 条规则的表比屏幕还长；
- 列宽被最长那条规则拉宽，其它列（规则号、条目数）被挤到视觉次要位置；
- 表格失去「一眼扫完、横向比较」的能力 —— 这本来就是表格唯一的优势。

改成 ⓘ 悬浮后：行高恢复单行、列宽固定，解释文字一条不少（悬浮里还附了备注）。

### 1.2 ⓘ 展开的内容必须可以选中复制（强制，需求 11207）

- 长文本用 `ⓘ` 承载，但**不能用 hover 型 `v-tooltip`**：鼠标一移到浮层上就消失，里面的文本根本选不中、复制不了。
- 统一用**点击型浮层**（实现参考 `Web/src/components/TextPopover.vue`）：
  - 点击 `ⓘ` 打开、点浮层外部或再点一次关闭（`v-menu` + `:close-on-content-click="false"`）；
  - 浮层内文本必须 `user-select: text`、`white-space: pre-wrap`、`word-break: break-all`；
  - 提供「复制」按钮，复制整段内容并提示。
- 判据：鼠标能在浮层内拖动选中文本、能用 `Ctrl+C` 复制、浮层不会因为鼠标移入而关闭。

## 2. 判定口径：什么算「长文本」

满足任一条即视为长文本，**必须**走 ⓘ 悬浮：

| 判据 | 说明 |
|------|------|
| 会换行 | 正常渲染宽度下超过一行（约 40 个汉字） |
| 长度不定 | 由数据决定长度（规则说明、备注、来源出处、错误信息） |
| 阅读频率低 | 只在少数行需要看，日常只需知道「有/无」 |
| 会撑列宽 | 单条最长值决定整列宽度，影响其它列可读性 |

以下**不算**长文本，直接展示（不要滥用 ⓘ，否则用户到处都要悬浮）：

| 类型 | 例子 |
|------|------|
| 枚举值 | `ACTIVE`、`insert`、`stock`（配合 `中文[值]` 风格，见 `MenuSpec.md`） |
| 标识符 | `rule_no`、`ftmm_symbol`、`usc`、`code`、`stock_id` |
| 数值/时间 | `priority`、`38 / 59`、`2026-11-10 19:30:27` |
| 名称 | 证券中文名、规则名称、市场名 |
| 短标签 | 「启用」「已停用」（`v-chip`） |

## 3. 强制规则

### 3.1 图标与配色

| 场景 | 图标 | 颜色 |
|------|------|------|
| 有内容 | `mdi-information-outline` | `primary` |
| 无内容（占位，告诉用户「这一列本来就没写」） | `mdi-information-off-outline` | `grey` |
| 危险/异常说明（如错误原因、冲突提示） | `mdi-alert-circle-outline` | `error` |

- 图标统一 `size="small"`，**不带文字**；需要让用户知道能悬浮时，在表格上方的提示行写一句「悬浮 ⓘ 图标查看完整说明」。
- 禁止用 `title` 原生属性代替 `v-tooltip`（无样式、延迟不可控、移动端不可用）。

### 3.2 悬浮内容结构

浮层里按「对象 → 正文 → 备注」三段，让用户不用回看行也能确认在看哪一条：

```vue
<v-tooltip location="top" max-width="560" open-delay="120">
  <template #activator="{ props }">
    <v-icon v-bind="props" :color="..." :icon="..." size="small" />
  </template>
  <!-- ① 对象：规则号 + 名称（或证券 + 市场） -->
  <div class="font-weight-medium mb-1">{{ rule.rule_no }} {{ rule.rule_name }}</div>
  <!-- ② 正文：完整原文，保留数据库里的换行 -->
  <div class="text-caption" style="white-space: pre-wrap">{{ rule.rule_desc || '（未填写规则说明）' }}</div>
  <!-- ③ 备注（有才显示），弱化配色 -->
  <div v-if="rule.remark" class="text-caption mt-2 text-medium-emphasis" style="white-space: pre-wrap">
    备注：{{ rule.remark }}
  </div>
</v-tooltip>
```

约定：

- `max-width` 取 `480`～`640`，禁止不设宽度（长文本会拉成一条横线）；
- `open-delay` 设 `120`ms 左右，避免鼠标划过表格时狂闪；
- 正文一律 `style="white-space: pre-wrap"`，**保留原文换行**（库里常带换行，压平后难读）；
- 内容为空的字段要给出明确占位（`（未填写规则说明）`），不要让浮层弹出空白；
- 浮层里只放**只读文本**；需要用户复制大段 JSON/日志时，放「查看」按钮打开 `v-dialog`（参考 `UscMappingView` 审计日志的 `before_json`/`after_json` 弹窗 + 复制按钮）。

### 3.3 列头

- 列头保留业务名（`说明`），**不要**写成 `说明（悬浮查看）` 这类把交互写进列名的话；提示语放在表格上方的说明行里。
- 多个长文本列合并展示时，按「对象 + 一、二、三段」组织在一个浮层里，不要再拆多个图标。

### 3.4 与「说明」卡片的分工

| 内容 | 放哪 | 参照 |
|------|------|------|
| 单行/单条的字段解释（随行变化） | 该行的 ⓘ 悬浮 | 本规范 |
| 整页的数据口径、表名、读法、业务约束 | 页面最底部唯一的「说明」卡片 | [`ExplainCardSpec.md`](ExplainCardSpec.md) |

不要把整页说明塞进某一行悬浮里，也不要把逐行解释抄到说明卡片里。

## 4. 自检清单（评审用）

- [ ] 表格里没有任何单元格会因文本长度换行超过一行（除 `v-chip` 徽章本身）。
- [ ] 每个长文本列都是一个 ⓘ 图标，且有内容/无内容两种图标态。
- [ ] 悬浮里第一行能确认「我看的是哪一条」（对象标识在前）。
- [ ] 悬浮 `max-width` 已设置，正文 `white-space: pre-wrap`，空值有占位文案。
- [ ] 表格上方有一句提示，告诉用户「悬浮 ⓘ 看完整内容」。
- [ ] 没有任何长文本仍以 `title="..."` 原生提示展示。

## 5. 反例

| 反例 | 问题 |
|------|------|
| 说明列直接 `{{ row.desc }}` | 行高、列宽被最长一条决定，表格失去横向比较能力 |
| 用 `title="..."` 代替 `v-tooltip` | 无样式、延迟不可控、移动端不可用 |
| 所有枚举值也加 ⓘ | 到处悬浮，反而降低扫描效率（枚举直接用 `中文[值]`） |
| 悬浮里塞 300 行 JSON | 浮层不可滚动、无法复制，应改为弹窗/详情页 |
| 无内容时不显示图标 | 用户无法区分「没有说明」和「这一列不支持说明」 |
