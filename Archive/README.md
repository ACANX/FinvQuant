# Archive（仓库级历史归档）

> 所属：FinvQuant · 存放：`Archive/`
> 用途：存放**已废弃、被替换或临时留档**的文件——只作历史追溯，**不参与构建、部署、测试与 CI**。

## 1. 什么该放进这里

| 适合 | 例子 |
|---|---|
| 被新实现替换、但需要保留对照的旧脚本/配置 | 旧的部署脚本、旧版 `.env` 模板、被合并的 compose 片段 |
| 一次性排查产物 | 迁移前的结构快照、问题复现用的 SQL、调试日志摘要 |
| 已作废的文档草稿 | 被改写前的方案稿（正式历史记录仍以 `Docs/CHANGELOG.md` 与 Git 历史为准） |
| 大文件历史留存 | 体积大、不宜放进 `Docs/` 的归档数据（如样本文件） |

## 2. 什么不该放进这里

| 不适合 | 正确去处 |
|---|---|
| 仍在使用的代码、配置、脚本 | 保持原位（`cmd/`、`internal/`、`Web/`、`Deploy/`） |
| 规范、接口、菜单、改造清单等有效文档 | `Docs/` 对应目录 |
| 对外可见的功能与版本变更记录 | `Docs/CHANGELOG.md` |
| 需要版本追溯的内容 | **依赖 Git 历史即可**（`git log`/`git show`），不必重复归档 |
| 数据库备份、构建产物、密钥 | `Deploy/Backup/`（不入库）、构建产物目录、密钥管理，**严禁入库** |

## 3. 使用约定

- **按来源建子目录**，不要平铺：`Archive/Deploy/`（部署相关）、`Archive/Web/`、`Archive/Internal/` 等。
- 归档文件**保留原文件名**，便于与原位置对照；如同一文件有多个版本，加日期后缀 `<原名>_YYYYMMDD.<扩展名>`。
- 进入 `Archive/` 的文件**应同步提交**（与删除/替换它的那次提交一起），并在提交信息里写明「归档原因」。
- 归档目录内的文件被引用时，文档中须明确标注「已归档，仅供参考，不再维护」，避免被误当作现行实现。
- 定期清理：确认无追溯价值（例如已被 Git 历史充分记录）的归档可直接删除，删除同样走提交记录。

## 4. 与其它目录的分工

| 目录 | 定位 |
|---|---|
| `Docs/` | **现行有效**的文档（变更日志、需求清单、规范、API/菜单/数据字典、改造清单） |
| `Docs/Refactor/` | 改造计划与执行清单（有编号、可勾选，属有效过程文档，不是归档） |
| `Archive/` | **已失效/被替换**的文件留档，不参与任何流程 |
| `Deploy/Backup/` | 数据库备份（运行期数据，不入库） |
